# Monitoring

Start/stop: `scripts\start-monitoring.ps1` / `scripts\stop-monitoring.ps1`. Charts: `prometheus-community/prometheus` (release `prometheus`)
and `grafana/grafana` (release `grafana`), versions pinned in `scripts/lib/common.*`.

## Low-spec choices
No Alertmanager, Pushgateway, node-exporter or PVs; scrape/evaluation 30 s; retention `2d` / `1GB`; kube-state-metrics kept (tiny, needed
for pod status/restart panels). Rules fire and are visible in Prometheus **Alerts** page; no notifications are sent. To add local notifications later
enable `alertmanager.enabled=true` in `monitoring/prometheus/values-lowspec.yaml` (+~100 MB RAM).
No ServiceMonitor is used (that needs the Prometheus Operator); a `kubernetes_sd` pod scrape job `cloudpilot` is defined in the values file.

## Access
```powershell
kubectl port-forward -n monitoring svc/prometheus-server 9090:80     # http://localhost:9090
kubectl port-forward -n monitoring svc/grafana 3000:80               # http://localhost:3000  (user admin)
```
Grafana's admin password is generated by the chart and read from a Kubernetes Secret (command printed by the start script). Nothing is exposed
beyond localhost port-forwards. Change/rotate credentials for any non-local use.

## Metrics exported by the app
`http_requests_total{method,endpoint,status}`, `http_request_duration_seconds_{bucket,sum,count}{method,endpoint}`,
`http_requests_in_progress{method}`, `cloudpilot_app_info{version,environment,git_commit}` (+ standard `python_*`/`process_*`).
`endpoint` is the route template; unknown paths collapse to `unmatched`; `/metrics` is not self-counted.

## PromQL (all use real metric names)
```promql
sum(http_requests_total{job="cloudpilot"})
sum(rate(http_requests_total{job="cloudpilot"}[5m]))
sum(rate(http_requests_total{job="cloudpilot",status=~"5.."}[5m]))
sum(rate(http_requests_total{job="cloudpilot",status=~"5.."}[5m])) / sum(rate(http_requests_total{job="cloudpilot"}[5m]))
histogram_quantile(0.95, sum by (le) (rate(http_request_duration_seconds_bucket{job="cloudpilot"}[5m])))
sum by (endpoint) (rate(http_requests_total{job="cloudpilot"}[5m]))
sum(up{job="cloudpilot"}) / count(up{job="cloudpilot"})
sum by (pod) (rate(container_cpu_usage_seconds_total{namespace="cloudpilot",container="cloudpilot"}[5m]))
sum by (pod) (kube_pod_container_status_restarts_total{namespace="cloudpilot"})
```
Verify targets first: Prometheus > Status > Targets, job `cloudpilot` must be UP. If cAdvisor panels are empty, check the
`kubernetes-nodes-cadvisor` target (chart default job).

## Alerts (`monitoring/alerts/cloudpilot-alerts.yml`)
| Alert | Condition | For |
|---|---|---|
| CloudPilotDown | no target or none up | 2m |
| CloudPilotHigh5xxRate | 5xx ratio > 5% | 5m |
| CloudPilotHighLatencyP95 | p95 > 0.5 s | 5m |
| CloudPilotPodRestarting | > 2 restarts in 15 m | 0m |
| CloudPilotHighCPU | > 80% of CPU limit | 10m |
| CloudPilotHighMemory | > 85% of memory limit | 10m |
Edit thresholds in that file and re-run `start-monitoring` (idempotent `helm upgrade`). Trigger demos: `curl localhost:8080/api/v1/simulate-error` in a loop (5xx), `.../slow?delay_ms=2000` (latency).
The rules were not unit-tested with `promtool` in this build.

## Dashboard
`monitoring/grafana/dashboards/cloudpilot-dashboard.json` (generated by `monitoring/grafana/generate_dashboard.py`): availability, total requests, req/s,
4xx, 5xx, latency p50/p95, CPU, memory, pod phase, restarts. Loaded from a ConfigMap by file provisioning - no manual creation.
In Compose mode, CPU/memory/pod/restart panels show "No data" (they need Kubernetes metrics).
